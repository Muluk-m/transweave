## Vision

### 10x Check
**"i18n 的 GitHub Copilot"** — 不是一个你打开来管理翻译的工具，而是嵌入开发工作流的智能翻译引擎。代码推送自动触发翻译、AI 质量评分、OTA 热更新、多模态上下文理解。

### Platonic Ideal
用户把 next-intl 加到项目里，跑 `transweave init`，CLI 自动扫描代码检测硬编码字符串。打开 Web 界面，AI 已完成初始翻译，每条标注置信度。低置信度翻译旁显示 UI 截图和上下文。修改翻译后 TM 自动更新，同类句式下次自动复用。审核者看到待审队列，快速批准。Webhook 通知 Slack。OTA 热更新不需要部署。

**Note:** OTA、多模态上下文、自动代码扫描不在本计划 scope 内，属于后续里程碑。

## Accepted Scope — Mini Specs

### 1. 翻译进度仪表盘
- **端点:** `GET /api/projects/:id/stats` 返回 `{ totalTokens, byLanguage: { [lang]: { translated, total, percentage } } }`
- **实现:** 单条 SQL 聚合查询（COUNT + GROUP BY on translations jsonb keys）
- **UI:** ProjectOverviewTab 加环形进度图组件（可用 recharts 或纯 SVG）
- **测试:** API 返回正确统计 + 空项目/单语言/多语言边界

### 2. AI 翻译置信度标记
- **来源:** LLM 在翻译时同时返回 `confidence: 0-100`（通过 prompt 要求 JSON `{ translation, confidence }`）
- **存储:** 翻译结果的 metadata（不加新列，存在 token 的 translations jsonb 中：`{ "en": { text: "...", confidence: 85 } }` 或保持现有 `"en": "..."` 格式 + 单独的 `translationMeta` jsonb 列）
- **UI:** 翻译单元格低置信度（<70）显示黄色边框 + tooltip
- **联动:** AI 翻译且 confidence < 70 → 状态设为 `draft`；>=70 → `translated`
- **降级:** DeepL/Google Translate 不返回 confidence → 默认 80

### 3. README 徽章
- **端点:** `GET /api/badge/:projectId` 返回 SVG（无需认证，公开端点）
- **SVG:** shields.io 风格，显示 "translations | XX%" + 颜色（绿 >80%, 黄 >50%, 红 <=50%）
- **缓存:** `Cache-Control: max-age=300`（5 分钟）
- **设置页:** 项目设置 Tab 显示 badge URL + 一键复制 markdown snippet
- **安全:** 只暴露百分比数字，不暴露翻译内容

### 4. 翻译 diff 对比
- **数据源:** 已有 `token_history` 表存储每次修改
- **API:** `GET /api/tokens/:id/history` 已有 → 需确保返回 translations 快照
- **UI:** TokenHistoryPanel 加 inline diff 视图，对比前后版本的每种语言翻译
- **diff 算法:** 简单文本 diff（字符级高亮变化部分），不需要复杂库

### 5. 导入冲突处理
- **检测:** 导入 JSON/YAML 时，服务端对比已有 tokens 的 key，返回 `{ new: [...], conflicts: [...], unchanged: [...] }`
- **Conflict 结构:** `{ key, existing: { translations }, incoming: { translations }, diff }`
- **UI:** 导入对话框增加 conflict resolution 步骤：显示冲突列表，每个可选 Keep/Override/Merge
- **Merge 策略:** 按语言合并 — incoming 有值的语言覆盖，existing 独有的语言保留
- **批量操作:** "Override All" / "Keep All" 快捷按钮
- **大量冲突:** >100 个冲突时分页显示

### 6. AI QA Check
- **触发时机:** 翻译保存时自动运行 + 手动触发全项目 QA
- **规则引擎（纯代码，不用 LLM）：**
  - **占位符一致性:** 检查 `{name}`, `{{count}}`, `%s`, `%d` 在源文本和翻译中出现次数一致
  - **HTML 标签完整性:** 检查 `<b>`, `<a>` 等标签配对正确
  - **长度异常:** 翻译长度 > 源文本 3x 或 < 0.2x 时警告
  - **未翻译检测:** 翻译与源文本完全相同时标记（排除 do-not-translate 术语）
  - **术语一致性:** 对比 glossary，检查翻译是否使用了指定术语翻译
- **存储:** QA 结果存在 token metadata（不需要新表）
- **UI:** Token 列表显示 QA 图标（绿色通过/红色有问题），点击展开问题列表
- **API:** `POST /api/tokens/:id/qa-check` + `POST /api/projects/:id/qa-check-all`

## Resolved Architecture Decisions

### Agent-to-Tool Dispatch
Agent Service **直接调用 service 层方法**（如 TokenService, GlossaryService, AiService），不走 MCP HTTP transport。MCP tools 和 Agent 共享同一套 service 层。这意味着：
- Agent endpoint: `POST /api/agent/chat` (JWT auth) → SSE response
- MCP endpoint: `POST /api/mcp` (API key auth) → MCP protocol
- 两者底层都调用相同的 service 方法

### Destructive Operation Confirmation (Agent)
Agent 执行破坏性操作时的确认 UX：
1. Agent 在 SSE 流中发送特殊事件 `{ type: "confirmation_required", action: "delete 15 tokens", tool: "batch_delete" }`
2. 前端显示确认对话框
3. 用户确认后前端发送 `POST /api/agent/confirm` → Agent 继续执行
4. 用户拒绝后前端发送 `POST /api/agent/cancel` → Agent 跳过该操作

### Batch Translate Execution Model
- 同步执行 + SSE 进度推送（不用 background job）
- 最多 5 个并行 AI 请求
- 每完成一条通过 SSE 推送进度 `{ completed: 5, total: 50, failed: 1 }`
- 失败的 token 记录错误信息，不阻塞其他翻译
- Provider rate-limit: 使用 p-limit 控制并发，429 响应时自动 backoff
